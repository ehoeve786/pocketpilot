# Changelog

## Unreleased

- M1: repository skeleton with build-logic, `core/model`, `core/common`, the app shell in `oss`, `pro` and `play` flavors, the module graph guard and CI.
- M2: local MCP server. `core/audit`, `core/orchestrator` (registry, dispatcher, sessions), `core/tools` with `device.info`, `capability/api` and `capability/device`, `server/mcp` (MCP SDK mapping) and `server/http` (Streamable HTTP on 127.0.0.1:8765 with a local bearer token). The app runs the server in a foreground service and shows the token and the Claude Code command.
- M3: eyes and hands. `capability/accessibility` (Accessibility service for snapshots, node actions, gestures and screenshots), `capability/apps` (launcher apps, launch, links), `capability/screencapture` (WebP/JPEG/PNG encoder) and `core/imaging` (crop, redact, scale, dHash). New tools: `screen.snapshot`, `screen.find`, `screen.wait_for`, `screen.wait_for_change`, `screen.capture`, `ui.tap`, `ui.long_press`, `ui.swipe`, `ui.type_text`, `ui.press_key`, `ui.global_action`, `app.list`, `app.current`, `app.launch`, `app.open_url`. Tool errors now repeat the error code and recovery hint in the text. `app.stop` and `app.send_intent` wait for Shizuku (M4) and the policy engine (M5).
- M4: Shizuku. `capability/shizuku` runs a privileged service as the shell user for input, raw screenshots, `uiautomator` snapshots, the foreground app, launches and the status bar. `core/capabilities` picks a backend per call in spec priority order, routes an element to the backend that took its snapshot, and falls back to Shizuku when Accessibility is off. Actions now wait for the screen to settle before the follow-up snapshot. Doctor v1 on the home screen shows each capability's backends and Shizuku's state, with a button to allow PocketPilot in Shizuku.
- M5: secure remote access. `network/api` and `network/tailscale` (an embedded tsnet node built with gomobile that joins the owner's tailnet and forwards HTTPS, including Tailscale Funnel, to a second loopback port), `server/oauth` (the phone's OAuth 2.1 server: metadata, dynamic registration, PKCE, rotating refresh tokens, revocation, lockout), `core/policy` (rate limits, app deny list checked before and after screen actions, confirmations for sensitive and destructive tools), `feature/approvals` (consent and confirmation prompts) and `feature/clients` (connected apps and the kill switch). The remote port accepts OAuth tokens only; the local token keeps working for apps on the phone. Debug builds are signed with a shared key so CI APKs update in place.
- M6: your own network. `network/wireguard` (userspace WireGuard on its own network stack, from a wg-quick config), `network/certificates` (Let's Encrypt certificates for the owner's domain through Cloudflare DNS, renewed 30 days before expiry, and an optional DNS record that follows the relay), `network/public-access` (ready-to-paste relay setups for GL.iNet and other OpenWrt routers, nginx and Caddy, plus the server's WireGuard peer) and `feature/network` (the Your own network card). The Go networking moved to `network/gonet`, shared by Tailscale and WireGuard, since a process holds one Go runtime. Secrets are encrypted with a Keystore key.
- M7: Agent mode. `agent/providers-api` (the normalized model contract), adapters in `agent/providers/anthropic`, `agent/providers/openai`, `agent/providers/gemini` and `agent/providers/openai-compatible` (DeepSeek, Qwen, OpenRouter, Groq, Mistral, Ollama, LM Studio, llama.cpp), `agent/model-registry` (bundled model descriptors with user overrides) and `agent/runtime` (the plan, act, observe loop as an `AGENT_RUN` session through the same dispatcher, policy and audit as remote clients; JSON fallback for models without tool calling; step, time, cost and image budgets; takeover and resume; transcripts). `feature/agent` adds the Agent mode card: model profiles with keys in the secret store, a connection test, new tasks, the live run and earlier runs. A notification lets the owner take over or stop a run from any app. New tools `settings.get` and `settings.set` read and change dark mode, Wi-Fi, Bluetooth, mobile data, airplane mode, location, Do Not Disturb, battery saver, stay awake, brightness, rotation, the four volumes, screen timeout, font size and animations through Shizuku, for the agent and connected apps alike. New app tools `app.stop`, `app.permissions`, `app.set_permission`, `app.set_appop`, `app.set_enabled` and `app.clear_data` run fixed `am`, `pm` and `appops` commands, refuse PocketPilot, Shizuku and core system packages, and show the exact change on the confirmation screen. `shell.exec` (not in the Play build) runs a raw shell command through Shizuku; it is off until the owner turns it on, and every command is shown in full and confirmed before it runs. The app now has Home, AI and Settings tabs at the bottom: Home shows the server, Doctor and how to connect, AI holds Agent mode, and Settings holds Accessibility, remote access, connected apps, the local token and the shell switch. A model profile can hold several API keys; a run moves to the next key when one hits its rate limit, runs out of credit or is refused. With "Switch models when one runs out" (on by default), a run whose model has no working key left goes on with the owner's other models in list order, skipping ones that call tools differently; the tightest cost limit in the chain holds. HTTP 402 now reports as out of credit. A run's "Allow settings changes" box lets `settings.set` run without a prompt for that run. Adapters send one request per step rather than streaming, and transcripts are JSON files until the database arrives.
- M5 follow-ups: a "… is controlling this phone" pill with a Stop button appears at the top of the screen while a connected app or Agent mode acts (an Accessibility overlay, or a notification when Accessibility is off). Stop ends the agent run, or refuses every connected app until the owner presses Allow again on Home. Tailscale Funnel turns itself off after 60 minutes without requests. Allowing an app to connect, approving an action, turning on the shell and turning off this lock ask for the owner's fingerprint, face or screen lock (Settings, on by default). Agent mode's notification no longer replaces the approval notification.
- M8: beta hardening. `capability/notifications` (a notification listener) adds `notify.list` and `notify.act`, which read and act on the phone's notifications and withhold those from apps on the deny list, such as banking and authenticator apps. `capability/files` adds `files.list`, `files.read` and `files.write` for folders the owner shares under Settings; paths cannot leave a shared folder and a write replaces a file only when asked. `feature/onboarding` is the eight-step setup guide shown on first start and reopened from Home; battery, Accessibility and notification access are granted through Shizuku when it is connected. Doctor re-checks every setup step with its fix.
- M8: more Shizuku tools. `adb.query` runs any read-only adb command (dumpsys, getprop, settings get, cmd ... status, ping, ip and more) without a prompt, refusing services that hold personal data; `adb.logs` reads logcat, crashes and ANRs with personal data masked. `app.activities`, `app.start_activity` and `app.send_broadcast` open an app at a given screen or trigger automation apps with an intent; `app.set_battery_optimization` and `app.set_standby_bucket` keep apps running in the background. `shell.exec` now asks once per exact command in a session.
- Automation hub (wave 1). The app now has Home, Automations, Tools and Activity at the bottom with Settings behind a gear, a shared `core/designsystem` theme, and per-tool Allow, Ask or Block modes that `core/policy` enforces (blocked tools disappear from tools/list). `core/automation` is a pure Kotlin engine with a data-driven catalog of about 40 triggers (time, device, battery, connectivity, apps, notifications, Quick Settings tiles, intents, MCP calls, other rules, variables), about 30 conditions in nested All, Any, None and Exactly one groups, and about 70 actions (every setting, apps, alarms and timers, notifications, screen and UI, speech, vibration, flashlight, HTTP, files, adb, shell in the sideload build, any tool, Agent mode, If/Else, Repeat, While, Wait, variables). Rules run as an `AUTOMATION` session through the same dispatcher, policy and audit as clients; sensitive tools a rule uses are confirmed by making the rule, while destructive tools and new shell commands still ask. `feature/automations` is the Automations tab: rule cards with Run and pin, a builder generated from the catalog, templates, Proposals and run History. AI apps get `automation.catalog`, `automation.list`, `automation.propose` (waits for the owner) and `automation.run`, plus `notify.post`. Agent rules share one monthly AI limit and pause with a notification when it is reached. Triggers listen while any rule is on, kept alive by a low-priority service; exact alarms and Bluetooth names are granted through Shizuku when a rule needs them.
- `app.directions` shows a Google Maps route to the nearest place of a kind, such as a gas station: it reads the distance on each search result, skips ads for other kinds of places and offices, and opens the route preview without starting navigation.
- `files.write` takes `append: true` to add text to the end of a file on a new line, leaving the rest of it unchanged.
- Tool calls accept "true", "false" and numbers written as text for yes/no and number arguments, as some models and clients with an old copy of the tool list send them.
- Agent chat. A new Chat tab makes Agent mode a conversation: the owner writes, the agent answers questions directly or works on the phone and then answers, and each answer waits for the next message with the whole conversation kept. Each turn gets the full step and time budget; the cost limit covers the whole chat. A chat stays on screen while the model thinks and steps aside only when a tool needs the screen; an answer that arrives while the owner is in another app comes as a notification that opens the chat. Tool calls fold into one line per turn, Take over and Stop sit above the input, New chat ends the current one, and earlier chats open read-only. A chat ends after 30 minutes without a message. Model profiles and run transcripts stay under Activity, Agent. The agent notification no longer shares its id with the automation service's.
- Agent mode works with every provider for every tool: `automation.propose` now describes its triggers, conditions and actions in full, the agent gives any list without an item schema one, and Gemini, which cannot take free-form objects, is asked for those as JSON text that PocketPilot turns back into objects. Gemini runs failed with HTTP 400 before.
- `app.directions` also routes to a place named outright, such as a hotel: when Maps opens that place's page instead of a list, it taps the page's Directions button, or asks Maps for the route by name.
- Automations wave 2. New triggers: arrive at or leave a place (the phone's own proximity alerts, no Google services), phone calls (ringing, answered, ended, missed; the number in the sideload build), text messages (sideload build), music or video starting, stopping or changing track, shake, face down or up, the proximity sensor, text appearing on screen, a log line, an app crash, a calendar event starting or ending, any broadcast by action, and a Home Assistant entity changing. New conditions: at a place, on a call, in a calendar event, and a Home Assistant entity's state. New actions: copy, move and delete a file (the new `files.copy` and `files.delete` tools), download a file, read a value from JSON, a Home Assistant action, read a Home Assistant entity, add a calendar event and read upcoming events. Home Assistant's address and access token are set under Automations settings, the token kept encrypted. Sensors, location, logs, the calendar and Home Assistant are only watched while an enabled rule uses them, and the permissions they need are granted through Shizuku at that point; call log and text message access exist only in the sideload build.
- Agent mode uses far fewer tokens. Each request sends full definitions only for the 15 tools most tasks need; the rest are listed one line each with their arguments, and their definitions are added once the model loads or calls them. In a chat, a finished turn keeps only its answer, not its tool calls and screens. Chat transcripts include the owner's messages and the agent's answers. `device.battery_usage` names the apps that used the most battery since the last full charge. `app.activities` and `app.permissions` work for apps whose package dump is very large, such as Settings. `app.open_url` takes `package` to open a link in a named browser.
- Liquid glass Home. `core/designsystem` adds `LiquidGlassBentoCard` (translucent gradient fill, gradient border, layered soft shadows, 24 dp corners, light and dark) and a `BentoPair` layout. Home is now a bento grid: the live status header, a command bar that sends a line to Agent mode and opens the chat, then Active automations beside Provider health and a telemetry tile (battery, network, tool calls in the last hour). Provider health shows each model of the chain as ready, rate limited with a "Back in" time, or down.
- Agent model pool. Keys of one profile can be used in turn (round-robin) so two Google AI Studio keys share the load. A rate limit (HTTP 429, or "rate limit" / "quota" in the error message), a timeout or a server error moves the run on to the next model in the owner's list, such as Groq, then OpenRouter or Mistral, and a failure inside an adapter no longer ends the chat.
- New trigger "Something tapped on screen" (`screen.click`): a rule runs when the owner taps a button or other view with a given label in an app, such as Accept in a delivery app. Clicks are listened to only while an enabled rule uses the trigger.
- The app version now follows the commit count (`versionCode` = commits on the branch, `versionName` = `0.1.<commits>`), so every CI build installs over the previous one instead of all being 0.1.0 (1). CI checks out the full history for the count.
- "Tap something on screen" can now find its target by text or label (as before), by view id (matched by its ending, such as `exit_button`), by the current keyboard focus, or by an X,Y point, and can long-press instead of tap. Existing rules keep working unchanged.
- "Wait until" now checks its conditions every half second instead of every two, takes an optional "Check every" setting (0.1 to 2 s) and accepts fractional timeouts such as 0.7 s. Rules that already set a check interval now actually use it.
- A shared rule now keeps its category and its starting variables on the other phone. Before, it landed under "Uncategorized" at the bottom of Rules and lost values such as Unassign Uber order's `first`, which made it do nothing. Variables named like credentials are still left out. A file from an older version that updates an existing rule keeps that rule's category.
- Lower battery use. The Accessibility service's notification-shade check runs only while floating buttons are up. Sensor-reading triggers sample once a second with hardware batching. In the pro and play builds, place triggers use Google's geofencing (reported within about two minutes, and no longer firing just because a rule was saved while the phone is already there), falling back to the platform's proximity alerts on phones without Play services; the oss build keeps the platform's alerts. Place alerts are set again when location is turned back on. Log line and app crash triggers follow the log through one Shizuku logcat that passes on only lines that may match, instead of starting a logcat every 10 seconds. Tailscale and WireGuard read their status less often while the link stays up (5 s, doubling to once a minute), and again sooner after a change or a Funnel switch.
- "Text appears on screen" triggers that name their apps no longer read the window's text while another app is in front, which was the costly part of watching for text. Triggers for any app work as before.
- The Home Assistant entity and action lists in the rule builder were empty for homes with more than a few hundred entities: replies were cut off at 100 KB, and the cut-off list did not parse. Lists may now be up to 8 MB, a reply over its limit is refused instead of cut, and a list that fails says why in the log.
- Agent mode and connected apps can use Home Assistant. `home.entities` finds devices by name or domain, `home.state` reads one, and `home.control` calls an action such as `light.turn_on` without asking. Locks, alarm panels, garage doors, gates and doors, valves, scripts and automations go through `home.control_secure`, which asks the owner on every call; `home.control` refuses them. New OAuth scopes `home:read` and `home:control`; Doctor lists Home Assistant.
- Agent mode sends the full definitions of the four `home.*` tools with every request, alongside the other core tools, so a model asked to control a device uses them instead of answering that it cannot.
- When a model asks to load a tool it already has, `tools.load` now says so and tells it to call the tool directly, instead of answering "Loaded" again. Gemini Flash loaded the home tools on every turn of a chat.
- `home.entities` ignores apostrophes, separators and filler words, so "Kaleb's light in the bedroom" finds an entity named "Kaleb’s Light". `home.control` waits up to two seconds for the device to report its new state, instead of reporting the old one from a plug that updates a moment late.
- Agent mode uses fewer requests and tokens: the system prompt tells the model that tools it already has need no loading, so a chat no longer spends a request on `tools.load` each turn, and `settings.get` no longer repeats the list of setting values that `settings.set` already carries.
- Rate limits are easier to read. When a model profile has several keys, the run log notes each key that was skipped and why, such as "Key 1 is out of quota: Gemini daily request limit (free tier) reached; trying key 2", and an error after every key failed says so. Gemini errors name the quota that was hit; a spent daily limit counts as out of quota, so the run moves on to a fallback model instead of retrying a key that will not work until tomorrow.
- Agent mode knows the time: the phone's date, time and zone come with the task and with each chat message, so "what time is it" or "in an hour" needs no tool call. New tool `device.location` gives the phone's coordinates, accuracy, age and nearest street address (from Android's own geocoder). It has its own `location:read` scope, which the owner ticks by hand for connected apps, and asks the owner on first use in a session.
- PocketPilot now shows up under "Open with" for a `.pocketpilot` file opened from Telegram and other apps whose file paths contain dots (such as `org.telegram.messenger`). Android's file-name match stopped at the first dot in the path, so only apps that accept every file were offered.
- PocketPilot is offered under "Open with" for a rule file received in Google Messages and other apps that pass it as a generic file. Any other file opened this way is read capped and parsed, and shows "can't read" instead of becoming a proposal.
- Settings: Tailscale Funnel's idle shutoff is now a choice: 1 h (default, as before), 8 h, 24 h or Never. Choosing Never asks for the owner's fingerprint, face or screen lock, as turning public access on does. Every request still needs an OAuth token the owner approved.
- Each rule has a run time limit ("Stop a run after": 30 min, the default as before, 2 h, 8 h or No limit), so a rule meant to run while an app is open, such as the Courier refresh, is no longer stopped and marked Failed after 30 minutes. A run that passes 20,000 log lines keeps going instead of failing; the log notes how many lines were left out and the last of them. An AI app changing a rule's limit waits for the owner, like a change to its variables.
- A proposal's notification ("Unverified: Claude … proposed a rule") now goes away once the proposal is accepted or declined, from the notification, the Proposals list or anywhere else. Notifications left over from proposals already handled are cleared when PocketPilot starts.
- "Text appears on screen" triggers now work in apps that redraw constantly, such as Uber Driver's live map. The trigger waited for the screen to stay unchanged for a second, which never happened there, so it never fired. It now checks at most once a second while the screen changes.
- Automations settings: "Screen text check rate" sets how often "Text appears on screen" triggers read the screen while it changes: 0.5 s, 1 s (default), 2 s, 3 s or 5 s. Faster reacts sooner and uses more battery.
- oss and pro builds declare the accessibility service an accessibility tool, so apps that mark parts of their screen accessibility-sensitive (Android 14+) can still be read. The Play build does not.
- "Tap something on screen" can find its target as the tappable thing beside a text, such as the unlabeled X beside "Delivery" on an Uber offer card: the nearest tappable element to the right of that text, on the same row.
- "Tap beside a text" touches the screen at the element's centre (Uber ignores accessibility clicks on its offer card's X) and stays inside the card or row around that text, so it can anchor on a price: beside "$" taps an Uber offer card's X whatever the card says, and never a button beside the earnings pill.
- A shared rule finds the rules it uses by name on the phone that opens it. "Turn a rule on or off", "Run another rule", "Another rule on", "Rule running" and "Another rule finished" pointed at the sender's rule ids, which no other phone has, so the shared rule did nothing there. The file now carries those rules' names, and the receiver links each to its own rule of that name, or warns when it has none.
- New action "Floating text" (`overlay.text`) shows a text over other apps, like a timer on screen. It can count by itself: `{stopwatch:name}` shows a rule's stopwatch, `{countdown:name:seconds}` the time left from it, and `{clock}` the time of day, redrawn once a second only while the screen is on. Each text has an identifier, so a later step can change or hide it (or hide all). Settings: alignment, background and text colour (#RRGGBB or #AARRGGBB), text size, padding, rounded corners, opacity, X and Y position and maximum width as a percentage of the screen, drag to move, hide on tap, hide after a delay, and a rule to run on tap or long press. Needs PocketPilot's Accessibility service.
- Colour settings now have a picker: tap one of 15 swatches (including a see-through black for backgrounds) or type a colour code, with a preview beside it. A colour the app cannot read is flagged before the rule is saved. Floating text's background and text colours use it, and accept codes without the "#".
- AI apps can read recent automation runs with `automation.history`: the same step logs and variables the Activity tab shows, newest first, for all rules or one. It is read-only, like `automation.list`.
